## :dart: O guia para alavancar a sua carreira

> Sass (Syntactically Awesome Style Sheets) é o pré-processador CSS mais usado do mercado: ele adiciona variáveis, aninhamento, mixins, funções, laços de controle e um sistema de módulos (`@use`/`@forward`) ao CSS, e depois compila tudo para CSS puro que qualquer navegador entende. Criado em 2006 e hoje mantido oficialmente pelo time do Dart Sass, ele está por trás de frameworks como Bootstrap e Foundation e continua presente em boa parte dos projetos front-end profissionais no Brasil, mesmo com a chegada de recursos nativos como nesting e `@layer` no CSS puro. Este guia reúne roadmap, documentação oficial, cursos gratuitos e pagos, livros, canais, ferramentas, projetos práticos e comunidades para quem está aprendendo Sass do zero até quem já usa `@import` e precisa migrar para `@use`/`@forward`. Os recursos em português e gratuitos vêm primeiro em cada seção, e todo link foi verificado. Use-o como apoio para os seus estudos, no seu ritmo.

## 🗺️ Roadmap

- [roadmap.sh — Frontend Roadmap](https://roadmap.sh/frontend) — O caminho completo de front-end em que pré-processadores como Sass se encaixam, ao lado de HTML, CSS e JavaScript.
- [roadmap.sh — CSS Roadmap](https://roadmap.sh/css) — Roadmap visual da comunidade sobre CSS moderno; cita Sass entre os pré-processadores relevantes de mercado.
- [Sass — Basics (guia oficial)](https://sass-lang.com/guide/) — O melhor ponto de partida oficial: visão geral de todos os recursos do Sass em uma única página, com exemplos lado a lado (SCSS e CSS gerado).
- [Sass — Documentação completa](https://sass-lang.com/documentation/) — Referência oficial de toda a linguagem, usada como mapa de tópicos por este guia.

**Trilha resumida** (siga na ordem; cada etapa tem recursos nas seções abaixo):

1. **Pré-requisito: CSS sólido** — Sass é uma extensão do CSS; domine seletores, box model, cascata, Flexbox e Grid antes de começar.
2. **Sintaxe SCSS vs. indentada (`.sass`)** — a esmagadora maioria dos projetos usa a sintaxe `.scss` (compatível com CSS); conheça as diferenças para a `.sass`.
3. **Variáveis (`$variavel`)** — cores, espaçamentos e fontes reutilizáveis em um só lugar.
4. **Aninhamento (nesting)** — organizar seletores refletindo a estrutura do HTML, com o operador `&` para estados e modificadores.
5. **Mixins e funções (`@mixin`/`@include`, `@function`)** — blocos de CSS reutilizáveis e parametrizáveis, e cálculos customizados.
6. **`@extend` e placeholders (`%nome`)** — compartilhar estilos entre seletores sem duplicar código.
7. **Módulos (`@use`/`@forward`)** — a forma moderna e recomendada de dividir o CSS em arquivos, substituindo o `@import` (deprecado).
8. **Estruturas de controle (`@if`, `@each`, `@for`, `@while`)** e **mapas/listas** — lógica e coleções de dados dentro do Sass.
9. **Arquitetura de projeto** — organização de pastas (padrão 7-1), variáveis de design system e integração com Bootstrap/Foundation.
10. **Build tools** — como compilar Sass com Dart Sass CLI, Vite, webpack (`sass-loader`) ou Parcel em um projeto real.

**Por onde começar:**

1. **Confirme que seu CSS está sólido** com a [documentação de CSS da MDN em português](https://developer.mozilla.org/pt-BR/docs/Web/CSS).
2. **Leia o guia oficial "Sass Basics"** em [sass-lang.com/guide](https://sass-lang.com/guide/) — 15 minutos para entender todos os conceitos centrais.
3. **Instale o Dart Sass** seguindo [sass-lang.com/install](https://sass-lang.com/install/) e compile seu primeiro arquivo `.scss`.
4. **Pratique variáveis e nesting** reescrevendo um CSS simples que você já tenha em Sass.
5. **Aprenda mixins e `@extend`** com a [referência de at-rules](https://sass-lang.com/documentation/at-rules/mixin/).
6. **Migre de `@import` para `@use`/`@forward`** lendo o anúncio oficial da depreciação: [`@import` is Deprecated](https://sass-lang.com/blog/import-is-deprecated/).
7. **Explore um projeto real** customizando as variáveis Sass do [Bootstrap](https://getbootstrap.com/docs/5.3/customize/sass/) ou do [Foundation](https://get.foundation/).
8. **Construa um projeto próprio** com Sass organizado em módulos e publique no GitHub como item de portfólio.

Seu primeiro Sass em 30 segundos:

```scss
// estilo.scss
$cor-primaria: #6366f1;
$espacamento: 1rem;

@mixin botao($cor) {
  padding: $espacamento;
  border-radius: 8px;
  background: $cor;
  color: white;

  &:hover {
    background: darken($cor, 10%);
  }
}

.app {
  font-family: system-ui, sans-serif;

  .botao-principal {
    @include botao($cor-primaria);
  }
}
```

Compile com `sass estilo.scss estilo.css` (Dart Sass instalado) e o resultado é CSS puro, pronto para qualquer navegador — nesting, mixin e a função `darken()` já resolvidos em tempo de build.

- [Sass — Mapas](https://sass-lang.com/documentation/values/maps/) — Estruturas chave-valor para organizar tokens de design (cores, breakpoints, espaçamentos).
- [Sass — Listas](https://sass-lang.com/documentation/values/lists/) — Coleções ordenadas de valores Sass.
- [Sass — Cores](https://sass-lang.com/documentation/values/colors/) — Funções de cor (`darken`, `lighten`, `mix`) e o novo suporte a espaços de cor amplos.
- [Sass — Módulos internos (`sass:*`)](https://sass-lang.com/documentation/modules/) — Funções embutidas para cor, matemática, listas, mapas, strings e introspecção.
- [Sass — Mudanças que quebram compatibilidade](https://sass-lang.com/documentation/breaking-changes/) — Índice oficial de breaking changes por versão, essencial antes de atualizar o Dart Sass.
- [Sass — Depreciação do `@import`](https://sass-lang.com/documentation/breaking-changes/import/) — Detalhes técnicos da migração obrigatória para `@use`/`@forward`.
- [Sass — API de cores nível 4](https://sass-lang.com/documentation/breaking-changes/color-4-api/) — Mudanças na manipulação de cor para acompanhar o CSS Color Module Level 4.

## 🤖 IA na prática

Sass é uma área em que a IA costuma acertar a sintaxe básica, mas erra no que já mudou: ela sugere `@import` em vez de `@use`/`@forward`, recomenda `node-sass` (oficialmente descontinuado) e às vezes mistura funções antigas de cor com a nova API de cores. Use a IA como **acelerador de refatoração e revisor de arquitetura**, não como fonte de verdade sobre o estado atual da linguagem.

**Para aprender**
- Peça para **explicar um conceito com um exemplo executável**: diferença entre `@extend` e `@mixin`, como funciona o escopo de variáveis, ou o que muda entre mapas e listas. Cole o exemplo no [StackBlitz](https://stackblitz.com/) para ver compilando de verdade.
- Cole um trecho de Sass legado com `@import` e peça: *"reescreva isso usando `@use` e `@forward`, mantendo o mesmo resultado visual"* — depois confirme contra a [documentação oficial de módulos](https://sass-lang.com/documentation/modules/).
- Peça **exercícios com gabarito** sobre o tópico que está estudando (mixins parametrizados, mapas de cores, `@each` em loops aninhados) e resolva antes de olhar a resposta.
- Peça para **explicar o erro de compilação** que o Dart Sass mostrou no terminal — as mensagens de erro do Dart Sass são detalhadas, e a IA ajuda a traduzir o contexto.

**Para trabalhar**
- Use [GitHub Copilot](https://docs.github.com/pt/copilot), [Cursor](https://cursor.com/) ou [Claude Code](https://code.claude.com/docs/en/overview) para: gerar variações de mixins existentes, converter CSS puro em Sass organizado por módulos, e revisar arquivos `.scss` em pull requests.
- Peça à IA para **migrar um projeto de `node-sass`/LibSass para Dart Sass**: ela consegue mapear a maior parte das mudanças de API, mas sempre valide contra o [changelog oficial de breaking changes](https://sass-lang.com/documentation/breaking-changes/).
- Depois de **cada** sugestão aceita, recompile o projeto e confira o CSS gerado — a IA às vezes propõe Sass sintaticamente válido que gera um CSS diferente do esperado (especialmente em `@each` com mapas aninhados).
- Peça sempre a versão do Dart Sass do projeto: recursos como cores de gamut amplo ou a nova ordenação de `@media` dentro de regras dependem da versão instalada.

**Limites e boas práticas**
- A IA **frequentemente sugere `@import` e `node-sass`**, ambos oficialmente descontinuados. Confirme sempre no [blog oficial do Sass](https://sass-lang.com/blog/) antes de aceitar uma sugestão de arquitetura.
- Ela tende a **inventar funções Sass** que não existem ou confundir funções nativas (`sass:math`, `sass:color`) com as antigas globais. Verifique na [referência de módulos internos](https://sass-lang.com/documentation/modules/).
- Peça para **explicar o "porquê"**, não só copiar o código — arquitetura de Sass (nomenclatura, organização de partials, uso de placeholders) tem convenções de time que a IA não conhece de antemão.
- Não cole tokens de design proprietários ou variáveis de marca de clientes em ferramentas de IA sem a política da sua empresa.
- Entenda o que você aceita: em entrevista e em produção, o Sass é seu — e quem mantém o projeto depois é você.

**Ferramentas de IA úteis para Sass:**
- [GitHub Copilot — documentação (PT-BR)](https://docs.github.com/pt/copilot) — Assistente de código integrado ao VS Code; gratuito para estudantes e com plano free limitado.
- [Cursor](https://cursor.com/) — Editor baseado no VS Code com IA para editar, refatorar e conversar com o projeto, incluindo arquivos Sass.
- [Claude Code](https://code.claude.com/docs/en/overview) — Agente de código no terminal: entende o repositório inteiro, incluindo folhas de estilo Sass e sua arquitetura de módulos.
- [Gemini CLI](https://github.com/google-gemini/gemini-cli) — Agente open source do Google no terminal, com cota gratuita generosa.
